# prism_aws_account (Resource)

Manages an AWS account onboarded to CloudKeeper. This resource sets up SAML/OIDC providers and configures cross-account access.

## Example Usage

```terraform
# Onboard an EXISTING AWS account.
resource "prism_aws_account" "production" {
  account_id   = "123456789012"
  account_name = "Production"
}

# Create a BRAND-NEW AWS account via the Account Factory.
# Requires the customer to have Org Services + a management account configured;
# otherwise apply fails fast with an "Account creation not enabled" error.
resource "prism_aws_account" "new_prod" {
  create_new      = true
  account_name    = "Acme Prod"
  root_email      = "aws-acme-prod@example.com"
  admin_role_name = "OrgAdminAccess"
  master_account  = "857639285487"
  owner_emails    = ["ops@example.com"]
  create_timeout  = "45m"
}
```

## Schema

### Required

- `account_name` (String) A friendly name for the AWS account

### Optional

- `account_id` (String) The AWS account ID (12-digit). Required in onboard mode; computed by the factory in create mode.
- `admin_role_name` (String) Create mode only: name of an IAM role created in the new account with AdministratorAccess, assumable from master_account. Required when create_new = true.
- `create_new` (Boolean) When true, Prism creates a brand-new AWS account via the Account Factory instead of onboarding an existing one. Requires root_email, admin_role_name and master_account, and management-account/Org-Services must be enabled for the customer.
- `create_timeout` (String) Create mode only: maximum time to wait for the factory + onboarding to finish (Go duration, e.g. "45m").
- `master_account` (String) Create mode only: 12-digit account whose root the admin role trusts. Required when create_new = true.
- `owner_emails` (List of String) List of owner email addresses for JIT (Just-In-Time) access approvals
- `root_email` (String) Create mode only: the root-user email for the new AWS account. Required when create_new = true.

### Read-Only

- `id` (String) The internal identifier for this AWS account configuration

## Behavior

- **Create (onboard mode, `create_new = false`)**: Registers an existing AWS account with Prism and creates the SAML and OIDC providers inside it. Before doing so, the provider preflights the account and fails without attempting the onboard if Prism cannot reach it.
- **Create (factory mode, `create_new = true`)**: Launches the Account Factory, polls until the new account is provisioned and onboarded, then records it. Bounded by `create_timeout` (default `45m`). No preflight — the factory provisions the cross-account role itself.
- **Read**: Looks the account up by `account_id`. If Prism no longer has it, the resource is removed from state and the next plan proposes recreating it.
- **Update**: `account_name` and `owner_emails` can be changed in place. Changing `account_id`, `create_new`, `root_email`, `admin_role_name` or `master_account` forces replacement.
- **Delete**: Removes the account's permission set assignments, then deletes the account record from Prism. The AWS account itself is not closed or altered.

## Requirements for onboarding an existing account

Prism reaches into each target account by assuming a cross-account IAM role — `CloudKeeper-SSO-Role` by default, set deployment-wide by the `AWSSwitchRoleName` stack parameter. It is not a per-resource setting and cannot be supplied from Terraform.

Onboarding fails if that role is absent from the target account, if its trust policy does not name the Prism account, or if its `sts:ExternalId` condition does not match. All three surface as an `AssumeRole` failure naming the account, and the underlying AWS error is reported verbatim.

~> **If the account has moved between AWS organizations**, check the role still exists. A service-managed StackSet with the default *Delete stacks* account-removal behaviour removes its stack — and the role with it — from any account that leaves the organization the StackSet targets.

To check an account without changing anything, call the onboard endpoint with `"dryRun": true`. It performs the same reachability check and reports the same errors, but creates nothing.
